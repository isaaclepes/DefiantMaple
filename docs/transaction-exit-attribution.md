# Windows transaction-exit attribution experiment

This benchmark follows the predeclared next experiment in the [accepted
2026-10-02 scan results](../benchmarks/source-scan-results/2026-10-02/README.md#one-bounded-next-attribution-experiment).
It reuses the unchanged 2,048-file, page-256 canonical fictional soak. The
source scanner, catalog and six frozen measured benchmark/production files are
not modified. Output is aggregate only.

## Run contract

One Windows job runs one parent process. The parent creates four matched pairs
sequentially in **BI/IB/IB/BI** order (B = baseline, I = exit-only instrumented).
Each trial is a fresh process with its own newly generated temporary fixture.
Both variants install the same phase hooks and keep `tracemalloc` active for
the original soak protocol. I additionally supplies an SQLite connection
subclass while a named scan phase is active. It reads `in_transaction`
immediately before delegating the original `Connection.__exit__`, records the
elapsed span in one of four state/exception strata, and preserves the original
return or exception. Explicit custom factories pass through unchanged.
Patches are process-local and restored on success or failure.

The workflow command is:

```text
python -m benchmarks.source_scan_exit_series series --count 2048 --page-size 256 --pairs 4 --trial-timeout 1440 --pair-timeout 3000 --revision "$GITHUB_SHA" --run-id "$GITHUB_RUN_ID" --run-attempt "$GITHUB_RUN_ATTEMPT" --job-id "$GITHUB_JOB" --head-sha "$PR_HEAD_SHA" --metrics transaction-exit-series.json
```

`--revision` must be the checked-out commit. `--run-id`, `--run-attempt` and
`--job-id` must match the current GitHub environment. The parent creates an
ephemeral public session token shared by its children; all trials must also
agree on code hashes, runtime metadata and canonical fixture. `--head-sha`
is the PR head commit and must be the second parent of the measured merge
commit. A child is
limited to 1,440 seconds; a pair, including cleanup, to 3,000 seconds. The
parent stops at the first timeout, cleanup or integrity failure and never
retries a trial. The process exits nonzero for an incomplete protocol. A
complete protocol with an inconclusive attribution screen exits zero because
it remains valid diagnostic evidence.

The three closed JSON schemas are `defiantmaple.source-scan-exit-trial.v1`,
`defiantmaple.source-scan-exit-pair.v1` and
`defiantmaple.source-scan-exit-series.v1`. A phase contains seven named
periods and four fixed strata. Each stratum reports count, total, min, max
and eight fixed duration buckets: less than 1 µs, 10 µs, 100 µs, 1 ms,
10 ms, 100 ms, 1 s, and at least 1 s. No SQL, row, source path, asset ID,
hostname, username, serial number, MAC address, absolute path or volume
label is collected. The original soak still verifies cancellation, fresh
restart, Offline/reconnection, stable identities, unchanged generated bytes
and cleanup. The public artifact checker must validate this closed schema
before archive publication.

## Predeclared diagnostic screen

All four pairs must complete. In each pair, the I/B indexing elapsed ratio
must be in **0.80–1.25**, inclusive. The **same** exit stratum must account
for **more than 50% of the full instrumented indexing elapsed interval** in
each of the four I trials. Otherwise the attribution verdict is
`inconclusive`. A stratum spanning a majority identifies an API span for a
smaller follow-up test; it does not establish a cause, a performance budget or
permission to change production transaction boundaries, rollback, locking or
durability. No timing from this diagnostic cohort is pooled with either
accepted hosted characterization cohort.

GitHub documents that [hosted runners are provisioned for each job and share
the job's VM across its steps](https://docs.github.com/en/actions/how-tos/manage-runners/github-hosted-runners/use-github-hosted-runners).
Its [hosted job limit](https://docs.github.com/en/actions/reference/limits)
allows the workflow's bounded 220-minute outer cap. A hosted job is one
identified runner session; it is not a physical reference desktop. The
generated fixture does not control OS cache, measure total process memory,
exercise large/varied media or a real SMB/NFS interruption, or establish
100k gallery/thumbnail responsiveness.

Results, raw report identity and variability belong in
[`docs/transaction-exit-benchmark-results/`](transaction-exit-benchmark-results/)
after the actual Windows run. Any next experiment must be chosen from that
evidence. No result is inferred from the local implementation tests.

The publication gate runs on a later PR synchronization. It skips another
Windows measurement only for an attempt-one, docs-only descendant of the
archived measured PR head, with a complete closed Windows report, matching
code digests and unchanged protected file bytes. It proves the current PR
merge's base/head parents and checks the measured merge's parents when that
older synthetic commit is still locally available. Archived execution origin
is separately checked against the GitHub run, log and artifact during
independent acceptance; this gate verifies safe reuse, not execution origin.
