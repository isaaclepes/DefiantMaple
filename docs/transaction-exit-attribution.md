# Windows transaction-exit attribution experiment

This benchmark follows the predeclared next experiment in the [accepted
2026-10-02 scan results](../benchmarks/source-scan-results/2026-10-02/README.md#one-bounded-next-attribution-experiment).
It reuses the unchanged 2,048-file, page-256 canonical fictional soak. The
source scanner, catalog and six frozen measured benchmark/production files are
not modified. Output is aggregate only.

## Run contract

One Windows job runs one parent process. The parent creates four matched pairs
sequentially in **BI/IB/IB/BI** order (B = baseline, I = exit-only instrumented).
Each trial is a fresh process with its own newly generated temporary fixture.
Both variants install the same phase hooks and keep `tracemalloc` active for
the original soak protocol. I additionally supplies an SQLite connection
subclass while a named scan phase is active. It reads `in_transaction`
immediately before delegating the original `Connection.__exit__`, records the
elapsed span in one of four state/exception strata, and preserves the original
return or exception. Explicit custom factories pass through unchanged.
Patches are process-local and restored on success or failure.

The Windows workflow runs this folded YAML command:

```yaml
run: >-
  python -W error::ResourceWarning -m benchmarks.source_scan_exit_series series
  --count 2048 --page-size 256 --pairs 4
  --trial-timeout 1440 --pair-timeout 3000
  --revision ${{ github.sha }} --head-sha ${{ github.event.pull_request.head.sha }}
  --run-id ${{ github.run_id }}
  --run-attempt ${{ github.run_attempt }} --job-id ${{ github.job }}
  --metrics transaction-exit-series.json
```

`--revision` must be the checked-out PR merge commit. `--run-id`,
`--run-attempt` and `--job-id` must match the current GitHub environment. The
parent creates an ephemeral public session token shared by its children; all
trials must agree on code hashes, runtime metadata and canonical fixture.
`--head-sha` is the PR head commit and must be the second parent of the measured merge
commit. A child is limited to 1,440 seconds; a pair, including cleanup, to
3,000 seconds. The parent stops at the first timeout, cleanup or integrity
failure and never retries a trial. The process exits nonzero for an incomplete
protocol. A complete protocol with an inconclusive attribution screen exits
zero because it remains valid diagnostic evidence.

The three closed JSON schemas are `defiantmaple.source-scan-exit-trial.v1`,
`defiantmaple.source-scan-exit-pair.v1` and
`defiantmaple.source-scan-exit-series.v1`. The instrumented report has seven
named phases, each with four fixed strata. Each stratum reports count, total,
min, max and eight disjoint duration bins: [0, 1 µs), [1, 10 µs),
[10, 100 µs), [100 µs, 1 ms), [1, 10 ms), [10, 100 ms), [100 ms, 1 s),
and at least 1 s. Bucket counts do not establish exact percentiles. No SQL,
row, source path, asset ID, hostname, username, serial number, MAC address,
absolute path or volume label is collected. The original soak still verifies
cancellation, fresh restart, Offline/reconnection, stable identities,
unchanged generated bytes and cleanup. The public artifact checker must
validate this closed schema before archive publication.

## Predeclared diagnostic screen

All four pairs must complete. In each pair, the I/B indexing elapsed ratio
must be in **0.80–1.25**, inclusive. The **same** exit stratum must account
for **more than 50% of the full instrumented indexing elapsed interval** in
each of the four I trials. Otherwise the attribution verdict is
`inconclusive`. A stratum spanning a majority identifies an API span for a
smaller follow-up test; it does not establish a cause, a performance budget or
permission to change production transaction boundaries, rollback, locking or
durability. No timing from this diagnostic cohort is pooled with either
accepted hosted characterization cohort.

GitHub documents that [hosted runners are provisioned for each job and share
the job's VM across its steps](https://docs.github.com/en/actions/how-tos/manage-runners/github-hosted-runners/use-github-hosted-runners).
Its [hosted job limit](https://docs.github.com/en/actions/reference/limits)
allows the workflow's bounded 220-minute outer cap. A hosted job is one
identified runner session; it is not a physical reference desktop. The
generated fixture does not control OS cache, exercise large/varied media or a
real SMB/NFS interruption, or establish 100k gallery/thumbnail responsiveness.
The reported `tracemalloc` peak covers Python allocations after fixture
creation while the soak runs, including verification and asset-identity/UUID
sets retained during tracing. It excludes untraced native allocations,
whole-process RSS, whole-machine memory and the known-byte source checks
performed after tracing stops. Runtime fields left `null` (including total
RAM, filesystem/storage and power/antivirus details) are unavailable, not
measurements of zero.

The [first complete hosted cohort](transaction-exit-benchmark-history/2026-10-03/first-complete/README.md)
is retained as separate diagnostic history: its protocol completed but its
attribution screen was inconclusive. A fresh cohort was required after a
gate-only Windows checkout proof repair. Its
[canonical result](transaction-exit-benchmark-results/2026-10-03/README.md)
passes the original diagnostic screen and identifies the delegated context-exit
API span only. Neither cohort is pooled with the other or with the accepted
source-scan cohorts. No result is inferred from local implementation tests.

The publication gate runs on a later PR synchronization. It skips another
Windows measurement only for an attempt-one, docs-only descendant of the
archived measured PR head, with a complete closed Windows report, matching
code digests and unchanged protected file bytes. It proves the current PR
merge's base/head parents and checks the measured merge's parents when that
older synthetic commit is still locally available. Archived execution origin
is separately checked against the GitHub run, log and artifact during
independent acceptance; this gate verifies safe reuse, not execution origin.
For a validated hosted Windows series, the gate requires exact Git-blob hashes
for the six frozen measured files. It authenticates only the two named new
probe modules by hashing their Git blobs after the exact LF-to-CRLF checkout
transformation observed in the first complete run. Every protected file,
including the gate, tests and workflow, still has to match its source-head,
current merge and worktree bytes exactly. The gate repair itself changed a
protected file after the first cohort, so a fresh full measurement is required.
That separate full measurement is now retained in the canonical report; the
gate's future docs-only reuse proof still depends on exact protected inputs.

The [SDD v0.2 review](sdd-v0.2-review.md) applies its finite benchmark
governance to this already bounded experiment. After the fresh cohort is
authenticated and screened, preserve its result and stop; an inconclusive
diagnosis is not a reason to retry for a preferred verdict. The proposed
reference profile and interaction budgets are separate release-design choices,
not thresholds for this hosted diagnostic.
