## Scope and baseline

Review the Phase 1a gallery usability increment against Task 20 and SDD v0.2 §§11, 15, 18–22. Baseline is `main` at `b0d1755fd344f7cb033c83d66413dff04997bfd4`. The four priorities are aspect-correct thumbnails, bounded responsive loading, an actual full-image viewer, and consistent Fedora/KDE application identity. This review does not expand the increment to the entire Phase 1a target or adopt the candidate numerical NFRs in SDD §19.2.

The starting Qt code paints each cached thumbnail into the entire rectangular image area (`AssetDelegate.paint`), which distorts non-square images. `ThumbnailWorker` has a bounded 32-item FIFO queue, but requests originate during paint and lack visible-viewport prioritization or stale-work pruning. Its close path waits without a fixed bound for the thread to finish; one decoder attempt is configured for six seconds, and cache-lock contention can add time. No original-image viewer exists. Current app/package naming is `DefiantMapleQt`, without a checked Linux desktop entry and icon identity. These are baseline observations, not findings against the pending implementation.

## Review checks

1. **Thumbnail display and cache.** Verify fit geometry on portrait, landscape, and square images, including EXIF orientation and high-DPI rendering. The default must preserve aspect ratio; any crop mode must say that it crops. Verify alpha presentation and a clear status for missing, unsupported, corrupt, or changed sources. Cache key/manifest validation must continue to bind asset ID, source hash and size, dimensions, decoder and output policy. Failures must not let an old preview masquerade as current.
2. **Scheduling and lifecycle.** Inspect which thread owns each `QPixmap`, `QImage`, model mutation, widget update, and signal receiver. Ensure visible cells and explicit viewer requests outrank speculative work. A bounded queue alone is insufficient if stale items occupy it after scroll, resize, filter or catalog refresh. Check identity tokens and source fingerprints again when results return, and test that a late callback cannot retarget a different asset at the same row. Review cancellation, individual decoder timeout, lock contention, exception handling, and closing latency, including a worker that has not completed. State observable concurrency, queue and memory bounds.
3. **Original-image viewer.** Confirm the inspected UUID/path/hash/size are captured at open; decode and full-source verification happen outside the GUI hot path under stated byte, dimension, pixel and time bounds. A small cached thumbnail cannot be presented as full resolution. Check fit, zoom, pan, fullscreen, keyboard close, resize behavior, orientation, alpha background choice, loading and failure messages. Test selection changes, replacement at the same path, unavailable originals, and closing while decoding. Clearly state any supported-format and color-profile limitations.
4. **Fedora/KDE identity and distribution.** Check visible window/application name, desktop file syntax and field-code handling, icon asset and installed path, executable command, KDE Wayland app-id/window grouping, and package inclusion. A source-tree launcher check and a frozen/package smoke answer different questions; record both honestly. Avoid persistent global desktop setting changes.
5. **Preservation and evidence.** Diff for source-media writes, catalog/metadata/scanner/SQLite durability changes, or edits to frozen evidence. Acceptance should use fictional generated sources and isolated catalog/cache, with before/after source and catalog digests as applicable. Native KDE/Wayland observations must identify runtime/backend and distinguish app-only captures from offscreen tests. Relevant tests and actual affected-platform CI, including Windows summaries, must be green or explicitly unresolved. Do not claim the SDD candidate performance budgets are passed without pre-adoption and a named workload/profile.
6. **Publication gates.** The two completed diagnostic workflows currently trigger on every pull request, and their conservative gates schedule fresh measurements for a GUI-code change. Confirm this PR scopes those workflows to the measured scan inputs, without changing frozen inputs or evidence. Preserve Core/Qt validation; do not schedule another characterization/attribution cohort for the gallery increment.
