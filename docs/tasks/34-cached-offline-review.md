## Pre-implementation design review — cleared for implementation

Reviewed Sol's private proposal `work/cached-offline-design-proposal-2026-10-05.md`
at SHA256 `be71217a49977b1ddb3c27ff581d14bae69a0bf500c0d702f34dd66bee3c7e37`.
The typed cache-only helper, captured target, bounded off-GUI decode, explicit
cached-view label and narrow fifth frozen-worker smoke fit Task32's scope. The
first proposal needed these clarifications, sent to Sol and Root:

- A 256-entry directory limit is below a naturally generated full slider cache:
  129 sizes from 96–224 each publish PNG and manifest (258 entries). Define a
  finite cap that includes supported pairs and bounded debris, or narrow the
  supported sizes honestly. State deterministic exact-missing fallback and
  exact-present-corrupt behavior; never present an alternate as an exact hit.
- The child must reject symlinked/reparse cache components, not just a leaf
  opened with `O_NOFOLLOW`. Define the component/descriptor containment check
  and a conservative unsupported-platform fallback. An in-flight replacement
  race may remain but must be disclosed.
- Cache-only catalog/path checks must compare captured strings and catalog
  fields without resolving, statting, opening or enumerating the original or
  source root. State exactly when paused/watching indexed entries may use the
  ordinary generator, when offline/denied/error/scanning/missing/nonindexed
  entries are cache-only, and how standalone null-source assets are labeled.
- Rating-only catalog revision changes must not masquerade as content changes.
  An explicit inspector keeps its captured UUID/fingerprint/path and reports
  path/source/metadata drift without rebasing to another selection. A matched
  manifest/output digest proves cache integrity and indexed-key binding, not
  authenticity against a same-user actor who replaces both PNG and manifest.
  Freshness labels must reflect that limit.
- Every newly displayed cache PNG, including one generated by the existing
  thumbnail worker, must be decoded/validated off GUI and handed back as a
  bounded image; the current `QPixmap(path)` GUI decode path cannot remain.
  The proposed 512 MiB child address-space ceiling requires actual packaged
  startup/decode evidence and a reviewed adjustment if unusable; it cannot be
  silently waived. Proposed SDD latency/RSS and cache-disk budgets remain
  unadopted.
