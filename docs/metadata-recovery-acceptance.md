# Verified metadata recovery acceptance protocol

Status: Core and Qt integration reviews cleared; focused/full Qt regression is green at the current reviewed checkpoint; native, hosted-platform, privacy, and recovery acceptance remain held.

This protocol defines the evidence needed for the first bounded metadata recovery slice. It uses generated fictional schema-6 catalogs and disposable local paths. It does not grant implementation or release authority. The recovery design in Task 41 has been independently reviewed and frozen for the current Core implementation, and Task 43 has cleared that Core for Qt integration. Acceptance remains held until the Qt implementation and all declared acceptance inputs are frozen and reviewed.

The bounded target is an explicit metadata-only verified backup, inspection, and isolated restore into a new, nonexistent local catalog location. The package contains a consistent schema-6 SQLite snapshot and a versioned manifest with snapshot size and SHA-256, verification result, package/catalog versions, and explicit exclusions for original media, derived previews/cache, out-of-catalog settings, and executable bindings. Source roots are reported as unverified. This is not a sanitization guarantee: freeform catalog metadata and stored paths may themselves contain sensitive text or credentials. Restore verifies the package before target creation, preserves catalog identity and user-authored metadata, and leaves restored sources guarded pending explicit review. The design requires no source media scan, mutation, or intended read; native evidence must not claim absence of reads from physical before/after digest equality alone. Restore does not auto-open the restored catalog or replace the current library.

This evidence may support only the bounded portions of FR-LIB-005, FR-RECOVERY-001, FR-RECOVERY-002, FR-RECOVERY-004, FR-RECOVERY-005, NFR-005, NFR-014, and NFR-015. It must not mark those full requirement rows Accepted. FR-RECOVERY-003 scheduled snapshots, FR-LIB-006/FR-RECOVERY-006 portable export/import, FR-META-008 selective redaction, FR-LIB-003 general multi-instance writer coordination, FR-LIB-007 cache/index rebuild, stable library identity, and full release recovery remain outside this slice. The schema-6 catalog has no stable `library_id`; the manifest must not invent one or claim that portion of FR-RECOVERY-005.

Do not change requirement IDs or statuses while preparing or executing this protocol. The current tracker statuses remain authoritative: FR-LIB-005 is Partial; FR-RECOVERY-001, 002, 004, and 005 are Partial for bounded Core evidence; FR-RECOVERY-003, 006, and 007 are Not Started; NFR-005 is Implemented; NFR-014/015 are Partial. ## Frozen acceptance inputs

Before running acceptance, record the reviewed design revision, implementation commit, source tree, complete declared input inventory and SHA-256 hashes, direct command lines and exit codes, runtime/platform versions, generated fixture definitions, and output destinations. Use generated fictional catalogs only. Raw logs containing paths remain private; public evidence must be sanitized and independently reviewed. Preserve the 13 October baseline and all 15 deployed outputs, including the sample binary recorded in the private baseline; compare bytes and relevant mode/time metadata before and after the acceptance run.


The exact restore deltas are the SQLite `application_id` state marker and, for each source, `enabled=0`, `health='paused'`, and `health_detail` set to `defiantmaple:restored-root-review:v1:` plus lowercase SHA-256 hex of `UTF8(source_id) || 0x00 || UTF8(root_path)` using the stored strings without normalization. Verify this value byte-for-byte, including its persistence after the global marker clears and its removal only through explicit captured per-source review. The Linux adapter accepts only owner-private directories backed by PCIe NVMe, with the reviewed mountinfo/sysfs evidence; macOS, Windows, other buses, and indeterminate backing refuse. A process that remains alive after kill because it is kernel-blocked remains owned for bounded later reaping and cleanup; the UI must report the unresolved outcome and must not claim it was reaped. These design limits are reflected in Task 41/43 and remain acceptance requirements, not results.

## Acceptance gates

1. **Core snapshot and restore.** Create a backup while a controlled separate writer commits before, during, and after the snapshot operation. Prove that the package is one coherent point in time and that its declarations and schema version match. Verify SQLite `integrity_check`, `foreign_key_check`, orphan-provenance checks, and the manifest digest against the closed snapshot bytes. Restore and compare exact generated asset IDs, revisions, taxonomy, aliases, assignments, provenance, ordered collections, source entries, and curation history. Compare every source row and column, allowing only the exact design-specified restored source fields and values. If `health_detail` contains a durable per-root hold, verify its exact sentinel/value after restore and after global pending-marker clearing, and verify normal source-enable APIs cannot bypass it before explicit captured root review. Enumerate every intended snapshot-to-restore difference, including the marker and exact disabled/paused/health-detail state; prove the backup remains unchanged. Prove that the live catalog and media/cache bytes are unchanged.
2. **Refusal and failure behavior.** Exercise altered manifest and snapshot digest, truncation, unsupported package/catalog versions, invalid schema, orphan relationship, missing or permission-denied paths, collisions with existing catalogs/packages, cancellation, and injected backup/publish/restore failures. Inject failures immediately after the atomic create-if-absent link, including final identity/readback, staging unlink, and directory sync where supported. The final path must remain a complete closed file when the link was created; report uncertainty accurately, retain rather than delete that final, and prove no overwrite or loss of a prior verified point. Record cleanup failures explicitly; never label blocked filesystem I/O as a hard cancellation bound.
3. **Qt and native behavior.** Exercise explicit backup selection, package inspection, and restore to a new location on a generated fixture. Observe pending state and a responsive event loop; confirm omission and unverified-root notices, path ownership, no automatic scan or source-media read/write, and actual worker shutdown on close. Include an invalid package and inaccessible target. Reopen the restored catalog and prove that metadata can be browsed while source roots remain paused/unverified and that the per-source hold appears as readable review status, never as its sentinel token. Ensure recovery replies cannot retarget the existing gallery or selection. Verify the current build honors the pending marker and refuses original thumbnail/inspector/comparison/external-open paths until review; verify source-backed cached-only catalog browsing remains available. Include assets with `source_id` NULL and prove original paths are guarded while catalog browsing remains available; a standalone-bearing catalog must refuse activation and report the count. Disable or refuse scanning while pending without probing a source. Test root-review activation with a captured mapping and a changed-mapping refusal; on successful review, clear the marker atomically while keeping sources disabled and their per-source holds in place. Verify ordinary source-enable and health-update paths cannot remove a hold; explicit captured per-source review clears only that source's hold after access checks and does not scan. Exercise pending `index_file` refusal before resolve/stat and unknown `application_id` refusal at raw gallery/cache openers. Confirm ordinary enabled-paused sources retain existing behavior. State explicitly that older builds ignoring `application_id` are outside the guard guarantee.
4. **Cross-platform and package evidence.** Run focused Core/Qt suites, one coordinated full Core/Qt discovery, generated Linux native acceptance, and package smoke only if the packaged runtime changed; preserve the existing seven gallery-filter smokes. On Linux, verify storage eligibility against physical backing-device/mount evidence, including sysfs when used by the adapter; verify source/cache/live-catalog containment with captured cache-root context and refuse unknown or unavailable context. Require exact-head hosted Windows/macOS/Linux summaries, named skips, artifact/privacy checks, and protected-source/output byte/mode/time preservation. A platform result supports only the command and head actually run.
5. **Independent review and publication.** Obtain independent implementation, test, native-result, and privacy reviews. Keep raw path-bearing logs private. Publish only sanitized generated evidence. A draft PR is reviewable only after these gates; merging and deployed-binary replacement are separate decisions.
