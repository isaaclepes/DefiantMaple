Status: protocol prepared against Task 45 and the independently cleared Task 44 design; implementation and acceptance remain pending. Task 46 cleared design SHA-256 `86db125e79638f0e7e34acd22f93c6e08ccbe188b26ede21db3c5b223a4bbc5c`. No acceptance or requirement transition is claimed.

## Scope

This matrix follows the proposed Task 44 contract: schema 7 stores one immutable canonical lowercase RFC 4122 version-4 UUID; package v2/schema 7 carries that UUID; the exact deployed package v1/schema 6 remains inspectable/restorable with identity absent on inspection and a fresh UUID assigned on each successful isolated restore. It does not qualify scheduled snapshots or retention, portable import/export, relinking, cross-instance writer coordination, platform release, or full recovery acceptance. Task 46 must clear the design before execution.

Use generated fictional schema-6 catalogs and disposable directories only. Keep raw catalogs, assigned UUIDs, private paths, media, logs and machine details outside public results. Never change deployed outputs or source media. Preserve FR-LIB-001/002 and FR-RECOVERY-001/002/004/005 as Partial unless a separate reviewed gate explicitly supports a narrower tracker update.

## Design inputs required before execution

Task 46 cleared Task 44's schema-7 table and immutable triggers, canonical UUID validation, schema/package compatibility matrix, migration and backup transaction, repeated legacy-restore assignment, old-client refusal, pending/source/standalone holds, and migration concurrency limits. Implementation still needs incremental review and a frozen manifest before execution. Supported live schemas 1–6 upgrade through the authenticated migration path; new initialized catalogs are schema 7. Packages are exactly v1/schema 6 or v2/schema 7. Existing SQLite migration backups must remain untouched. Do not imply a safe mixed-version concurrent writer contract; the reviewed design requires other app instances closed for upgrade.

Before running the matrix, freeze the reviewed design hash, implementation revision/tree, test and runtime input hashes, fixture definitions, commands, direct exit codes, platform/runtime versions, and output destinations.
