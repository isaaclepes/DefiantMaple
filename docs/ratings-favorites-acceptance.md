# Ratings and favorites acceptance

## Purpose and status

This record defines generated-fixture acceptance for the explicit ratings and favorites increment. It is not a user-study report and contains no inferred user feedback. The measured implementation is based on `60ebf881e6bb85316042100e3ed8beb119acf400` plus the implementation files identified by hashes in the evidence receipt. Attempts 1 and 2 stopped at the native editor focus gate while the KDE session was locked. Attempt 3 ran after the session was unlocked and passed the bounded native interaction, save, persistence, undo, conflict, integrity, and cleanup gates. All three attempts remain in the public history; the earlier failures are preserved as historical outcomes.

The native run is limited to the user-authorized flows in Task 23: explicit unrated/1–5 rating and independent favorite state, typed filters, captured-asset targeting, persistence, and guarded catalog undo across reopen. It does not qualify broad metadata synchronization, bulk editing, filesystem undo, release packaging, or cross-platform accessibility.

## Generated fixture and isolation

The probe uses only generated fictional media and a temporary catalog, source roots, verified migration backup, cache, XDG data, and private diagnostics under one empty external evidence directory. It records byte digests for every generated original before the run and checks expected content after deliberate generated-fixture mutation scenarios. It never opens user-library media or captures the whole desktop. App-window screenshots show only generated fixtures and may visibly contain synthetic catalog identifiers and the isolated temporary root; their hash and scope are recorded.

The old catalog is created with the exact pre-increment schema and deterministic rows, then opened through the production migration path. Seed enough rows to exercise stable IDs, a source row, tag/entity assignments, and an ordered manual collection. The acceptance helper will record the old/new schema version, verified backup path-independent digest and integrity result, and before/after digests/counts for the relevant catalog records. Original asset UUIDs, source mapping, tag/entity assignments, and collection order must survive migration unchanged. Migration-failure rollback is covered by regression tests; the native probe does not inject a database failure into the visible desktop run.

## Interaction and persistence gates

The generated gallery must demonstrate these independent behaviors:

- `unrated` is distinct from each integer rating 1–5; favorite is a separate boolean. Setters and UI choices reject invalid rating types/ranges atomically. Reapplying an unchanged value is a no-op and does not create a misleading undo edit or revision.
- Rating and favorite filters expose explicit all/yes/no and unrated/individual-rating semantics as supported by the finalized API. Each filter composes with an existing text or review-state filter; the probe records expected and observed generated fixture-key membership for each query.
- Open the editor for generated asset A, change gallery selection to B, then save. The dialog's captured identity must update A only. It must show the target and truthful success, validation, stale-write, or conflict feedback. Focus, keyboard access, and named controls are recorded separately from offscreen evidence.
- Close/reopen the catalog and gallery and verify ratings/favorites persist. Scan the same generated source again and verify explicit user values are unchanged; scanner observations do not silently write these fields.
- Perform a real rating/favorite edit and retain its durable undo identity. Close the app and catalog, reopen, and undo; verify both values return to their prior state and the undo record is consumed or otherwise becomes unavailable according to the API contract.
- Reopen before testing stale undo. Create a later metadata revision that changes a value and then returns it to its former value (ABA). The old undo must refuse because the revision advanced. Separately exercise undo refusal after a generated asset's content revision and path revision change. The probe records before/after state and the exact conflict outcome, without claiming a generic mutation-journal guarantee.

Field authority is explicit: rating and favorite are user-managed catalog fields. Only explicit edits are user-authored; migrated/default `NULL` and `false` values do not claim authorship provenance. Import, rescans, and automated candidates may not silently populate or replace these fields. This probe does not claim embedded metadata synchronization or conflict resolution for other fields.

## Result

The implementation API is frozen. Local implementation tests report 215 Core and 42 Qt tests passing; these are separate from native desktop evidence. Attempt 3 ran on Nobara 44 KDE Plasma Wayland with Python 3.14.7, Qt 6.11.2, a 2560×1080 display at DPR 1.0, four generated assets, two generated sources, and isolated catalog/cache/XDG state. It migrated a v4 catalog to v5, verified the backup and migrated integrity as `ok`, found zero foreign-key violations, and preserved the seeded rows and collection order. Four completed scans left explicit ratings/favorites unchanged. All three composed filter cases returned the expected fixtures.

During attempt 3, the dialog remained active and the automated native Qt event sequence reached the Save control. The test changed gallery selection after opening the editor and confirmed the captured asset alone was targeted. A stale external update was refused with reload guidance; after reload, the explicit save succeeded. The native gate verified the 5-star and Unrated keyboard endpoints, tab navigation, favorite Space toggles, a no-op with no undo entry, and refusal of four invalid type/range inputs. After reopening, durable catalog undo restored the prior rating/favorite values. A metadata ABA revision advanced from 2 to 4 and made the old undo unavailable; separate generated-content and rename changes also caused undo refusal. Catalog integrity passed, foreign-key violations were zero, the Qt application ID was `io.github.isaaclepes.DefiantMaple`, and the window closed. Thumbnail workers were disabled; this run measured no thumbnail performance, resource usage, or timeout bounds. It collected no KDE compositor identity and is not human accessibility or cross-platform qualification.

Attempts 1 and 2 retain their original probe hashes and focus-gate failures: attempt 1 timed out after editor activation was not observed; attempt 2 saw a Qt-visible dialog without native exposure or an active/focused application window. Root confirmed the desktop session was locked through a read-only state check. Neither attempt is counted as a pass or a product defect finding.
